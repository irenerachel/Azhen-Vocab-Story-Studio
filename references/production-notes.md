## 1. 写故事文件

动画由两部分组成：`lib/engine.js`（引擎，所有故事通用，不改）和 `page/story.js`（这个故事的配置和画面，每次重写）。`page/narration.js` 由 `voice_prep.py` 生成。骨架见 `assets/engine/story-skeleton.js`，完整例子见 `assets/example-cinderella/story.js`。

`story.js` 的结构：

```js
VocabStory.init({ aspect, label, duration, music, locs, fact, ground, sceneT, holds, title, end });
// 之后下面这些都是全局函数/常量
function drawKitchen(t) { ... }                 // 每个场地一个，t 是故事时间
VocabStory.start({ kitchen: drawKitchen, ... });
```

`init` 之后可以直接用的东西：

| 名字 | 作用 |
|---|---|
| `W` `H` | 画布大小：横版 1920×1080，竖版 1080×1920 |
| `put(场地, 图名, {x, y, h, flip, rot, skew, sx, sy, ox, oy, z})` | 按脚底位置摆一张图；脚的 y 越大越靠前，自动盖住后面的人 |
| `SZ(图名, g)` `gAt(场地, 脚y)` | 身高表和地面透视，见第 2 节 |
| `camera(场地, {z, fx, fy, dx, dy, t})` | 推拉镜头，自带轻微手持漂移，不会露出背景边缘；返回 `{z, tx, ty}` |
| `squash(t, t0, 幅度)` | 落位挤压回弹，展开进 `put` 的参数里 |
| `puff(fx, t, t0, x, y, 半径, {dur, seed, fill, n, drift})` | 手绘烟团：遮住换姿势、落地扬尘、出场 |
| `star` `twinkle` `zap` `speed` | 星光、一闪、魔法轨迹、速度线 |
| `shake(t, t0, 幅度)` | 震动量，加到 `camera` 的 `dx / dy` 上 |
| `C(故事时刻, 音效编号, 音量dB)` | 声音提示，自动换算成视频时间。音效编号用 `$CTV/scripts/sound_library.py search` 查 |
| `L[场地].fx` | 这个场地的特效层（传给 puff 等） |
| `TITLE` | 标题牌元素，自己写它怎么离场 |
| `makeInset(场地, 图名, {left, top, size})` | 放大圆框，特写被字幕挡住或太小的细节 |
| `setIrisFocus(x, y)` | 片尾光圈收向哪里（屏幕坐标，用 `camera` 的返回值换算） |
| `E` `P` `lerp` `spring` `clamp` `hash` | 缓动、进度、插值、弹簧、随机 |

写场景函数的套路：
- 常量里先列出事件时刻（如 `ZAP1 = 14.15`），画面和 `C(...)` 都引用同一个常量，声画才不会各算各的。
- 姿势切换不补间：用一团烟遮住换图，再配 `squash` 落位。
- 进出场配速度线；每个动作先预备（下蹲、后仰）再爆发。
- 换场地时引擎自动做扫屏转场；同一场地内的连续两场用镜头推拉衔接。
- 片尾光圈的 `path` 换成主线物件的轮廓：以原点为中心、约 200 宽，只用 `M / L / C` 加绝对坐标（不要用 `A` 弧线和相对坐标）。
- 时间都写“故事时间”。`holds` 加的停顿由引擎换算，场景函数不用管。

## 2. 角色比例与地面透视

插图里人物大小各不相同，不能直接按图片高度摆。
1. 运行 `contact_sheet.py` 出带刻度的联系表，读出每张图里主角色头顶和脚所在的刻度。
2. 定一个基准：主角站立身高 g。每张图的显示高度 = g × 系数，系数 = 该角色相对主角的身高 ÷ （脚刻度 − 头顶刻度）/100。写进配置的 `fact`。
   - 灰姑娘的相对身高：主角 1、继母 1.08、瘦姐姐 1.0、胖姐姐 0.68、王子 1.1、教母 0.68。
   - 弯腰的姿势比站直矮（约 0.9～0.98）；抱着高物体的图，人只占图的下半部分（衣服山那张系数 1.45）；坐姿约 0.53。
   - 道具和动物也进 `fact`（南瓜 0.33、鸡 0.42、马车 0.95），这样它们会跟着透视一起缩放。
3. 一张图里有两个体型差很多的人（两个姐姐），用 `split_sprite.py` 拆成两层分别缩放。
4. 地面透视：`ground[场地] = [地平线 y, 参考身高, 参考脚位 y]`，`gAt(场地, 脚y)` 给出那个深度的主角身高。先在背景图上找到地平线（地板与墙的交线、远山脚），再定一个“站在这里看着合适”的参考点。
5. 换了某张图后，这张图的 `fact` 和道具端点（如扫帚头坐标）要重新量。

## 3. 前后遮挡

- `put` 已按脚的 y 设置 `zIndex`，靠前的人盖住靠后的人；特效层（烟、星）永远在最上面。
- 背景插图是一整张，前景物体（栅栏、灌木）没法盖在角色前面。所以先看背景图：前景有遮挡物时，把角色的脚放到遮挡物后面的空地上，再用 `gAt` 让他们按透视变小，必要时整体把镜头推近 1.1 倍左右。
- 场地图层自己有 `zIndex`，所以字幕、转场时针、片尾这些全局层要给更高的 `z-index`（示例里是 100～120），否则后面的场景会把它们盖住。

## 4. 字幕区与画面安排

- 横版：双语字幕框上沿约 y=817（长句换两行时），英文 38px、中文 32px，自动均衡换行。
- 竖版：字幕框更窄（最宽 940px），长句会换成 3 行，上沿约 y=1500；框底离画面底边 210px，避开平台按钮。生词卡在右上角 y=200 起。竖版背景要按 9:16 出图，场景坐标按 1080×1920 写，不能把横版坐标直接搬过来。
- 关键动作和小道具要放在字幕框上方；镜头推近受“不露边”限制，没法把画面底部的东西推上来。
- 每一场都要检查脚和手持道具（扫帚、魔杖、鞋）有没有被字幕框挡住，不只看关键动作。灰姑娘第一场原来脚放在 y=1000，扫帚头和脚全被字幕盖住；改成脚在 y=820、按透视缩小后才露出来，身后的人物也要跟着往后挪（y 更小），保持前后关系。
- 实在只能在画面底部发生的细节（例如脚上的鞋），用“放大圆框”特写：一个圆形遮罩里放同一张图的放大局部，弹出几秒再收起（示例里的 `inset`）。
- 生词卡在右上角，念到该词时弹出。时刻来自 `voice_prep.py` 的 whisper 听写（比按字符位置估算最多能准 0.6 秒）；某个词没听出来时只有它退回估算。

## 5. 配音与“等旁白”停顿

- LibTV 语音：模型 `speech-2.8-hd`，音色 `English_Graceful_Lady`。`synthesize_speech` 不接受语速参数，用默认语速。每场一句，单独合成，方便对时和单句重做。
- `voice_prep.py` 负责下载、量时长、whisper 听写。它打印的“原稿 / 听写”对照就是念错检查：数字会被听写成阿拉伯数字（twelve → 12），属正常；专名、生僻词不一致时去听一下原声。
- 配音比画面长时，不改语速、不拉慢动作：在每场动作已经落定的地方加 `holds` 停顿 `[故事时刻, 增加的秒数, 停顿内走速]`。走速 0.08 接近定住（镜头和星光还在轻微动），0.2～0.3 是慢动作。
- 加多少：`export_timeline.mjs` 会报“第 N 句旁白还没念完，下一句就开始了（重叠 x 秒）”，就给第 N 场加 x 秒左右的停顿，直到不再报。
- 停顿不能盖住事件：停顿内故事只走 `增加秒数 ÷ (1 − 走速) × 走速` 秒，事件时刻要落在停顿外。
- 让关键画面落在对应的词上：例如“turned the broom into a chicken”念到 chicken 时鸡才出现，就在魔杖挥动前加停顿。

## 6. 渲染、混音与检查

- 渲染器在 code-to-video-studio：`node $CTV/scripts/render_page.mjs page --out build/vN`，画幅读 `page/aspect.txt`。需要 `PLAYWRIGHT_MODULE=项目/node_modules/playwright`；playwright 版本要和本机已下载的 chromium 匹配，`new_project.sh` 已经处理（chromium-1140 对应 playwright 1.48.2）。
- 想快速过一遍版式审查而不等整片：加 `--fps 10 --samples 1`，几分钟就能跑完，只用来查错，不当成片。
- 先用 `preview.mjs` 抽几个时刻看构图，再整片渲染（约 2000 帧，十几到二十几分钟，放后台）。
- 版式审查会拦住内边距不足的文字容器（例如生词卡大字左右要 ≥ 0.8 倍字号），按报错加内边距重渲。
- 音乐音量 -27 dB 给旁白让路；`mix_voice.py` 把配音按时间轴混入，两遍 loudnorm 到 -14 LUFS，同时出双语 SRT。
- 改完引擎或故事结构后想确认没改坏：改之前抽一组帧存起来，改之后同样的时刻再抽一组，逐像素对比。
- `check_video.py` 做技术检查；“最长静止 3 秒”的提示通常就是加的停顿，确认是有意的即可。
- 音量比例没有人耳试听过，交付时要写明。

## 7. 字体与授权

- 默认：中文寒蝉圆黑体（Medium 正文字幕、Bold 标题），英文 Fraunces 600。两者都是 SIL OFL 1.1：可商用、可嵌入网页、可截取子集。寒蝉圆黑体的授权文件里没有声明保留字体名。
- 用户要换中文字体时，先查授权：视频用字和网页嵌入是两回事。乐米沐和圆体允许视频商用，但明确禁止嵌入网页和拆分字体文件，所以不能用在网页上（当时的折中是把网页标题渲染成图片，用户不满意，最后换成了寒蝉圆黑体）。
- 猫啃网字体页的“字体授权”一节会写清楚是否 OFL、是否允许嵌入；GitHub 上的开源字体单个字重用 `raw.githubusercontent.com` 下载，网络不稳时加 `--retry`。
- 动画页加载完整原始字体文件（`new_project.sh` 已复制到项目里）；网页由 `build_quiz.py` 按实际用字截取后内嵌（约 75 KB/字重），改了题目数据重新生成即可。

## 8. 网页：发布与本地测试

- 发布到 Artifact：网页本身 + `files` 里的 `story.mp4`（压到 1280 宽、crf 27，约 8～9 MB，单个文件上限 15 MB）、`img/poster.jpg`、`img/<词>.webp`、`audio/<句>.mp3`。
- 一次传太多文件容易超时：先发网页和小文件，再单独发一次只带 `story.mp4`。
- 这台机器连 claude.ai 时断时续：发布报网络错误时先 `list` 看有没有发上去，再重试。分享链接需要登录同一个账号才能打开。
- 平台会自动加字符集和 viewport 声明，模板里没有；本地测试用 `build_quiz.py --local` 生成的 `_local.html`，测完删掉，别发布它。
- 平台自带 `[hidden]{display:none}`，模板里也写了，避免本地测试时两个视图同时出现。
- 只有夜晚星空：试过白天模式（浅色天空 + 深色答题卡），用户觉得不好看，删掉了。

## 9. 清理

成片确认后删除：`build/` 下各版本的中间帧和无声画面、预览抽帧、`assets/raw` 可重新下载的原始素材副本（保留透明 PNG 成品及来源记录）、不再使用的字体。旧版成片属于交付物，问过用户再删。
